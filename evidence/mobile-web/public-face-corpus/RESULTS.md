## 실행 환경과 범위

화면 조작용 브라우저가 연결되지 않아 독립 WSL 가상환경 `/home/daeha/.venvs/mobile_web_service_face_eval`에서 CPU 추론을 실행했다. 앱에 포함된 바로 그 `face-short-range.tflite` 파일을 MediaPipe Python 0.10.32로 읽었다. SHA256은 `b4578f35940bf5a1a655214a1cce5cab13eba73c1297cd78e1a04c2380b0152f`다. 실제 앱의 `faceScans`, `projectFace`, `refinementScans`, `mergeFaces`, `faceRegions` 함수를 Node bridge로 호출했다. 이 함수들을 Python으로 다시 구현하지 않았다. 동일 모델에 대한 전체 사진 1회와 현재 구역 검사를 같은 환경에서 비교했다.

실행: WSL의 위 venv에서 `python tools/local/evaluate_face_corpus.py`. 최종 실행 종료 코드 0, 16장 오류 0, 앱 소스 hash 불변, 모든 사진 원본 바이트 불변. 원시 구역·confidence·합친 탐지·좌표와 버전은 [results.json](wsl-results/results.json) 및 각 `*-raw.json`에 있다. 별도 설치한 의존성은 이 검사 venv에만 있으며 서버 requirements나 PythonAnywhere에는 추가하지 않았다. libGL 없는 WSL 실행을 위해 검사 환경에서 GUI OpenCV를 headless 배포판으로 교체했다.

**Python 네이티브 추론과 브라우저 WASM 실행기가 다르고, JPEG decode·resize도 Pillow이므로 결과의 브라우저 일치를 보장하지 않는다.** 이번 검사에서는 실제 canvas 모자이크 픽셀·worker·물리 iPhone Safari·PythonAnywhere 작성 화면을 실행하지 않았다. 그림은 진단 좌표를 그린 이미지이며 실제 모자이크 화면이 아니다.

## 정답 좌표가 있는 9장

공식 예제 얼굴 사각형 43개 중 **43개 모두 현재 가림 영역 하나에 80% 이상 포함**됐다. 같은 환경의 전체 사진 1회 검사는 17개였다. 이는 이 표본의 좌표 포함 결과이며 얼굴을 완전히 가렸다는 보증이나 일반 정확도 100%를 뜻하지 않는다.

가림 영역과 정답 사각형의 IoU ≥ 0.3에서 최대 일대일 대응을 계산하면 현재 TP 37 / FN 6 / FP 16, 전체 1회는 TP 11 / FN 32 / FP 4다. 과도하게 큰 가림 영역은 얼굴을 덮어도 IoU가 낮아 대응에서 탈락할 수 있다. 따라서 **이 FN 6개를 실제로 전혀 가려지지 않은 얼굴 6개라고 해석하면 안 된다.** 주석 밖 실제 얼굴·중복도 FP에 포함될 수 있어 FP 16개를 모두 배경 오탐이라고도 단정하지 않는다. 이미지별 육안 검토를 함께 사용한다.

## 결론과 후속 검증 항목

구역 검사는 작은 얼굴을 찾는 데 도움을 주지만 현재 confidence·중복 처리 조합은 비인물 오탐과 과도한 범위 합침을 허용한다. 다음 수정에서는 얼굴 포함률을 유지하면서 비인물 기각·중복·과도한 범위를 함께 평가해야 한다. 이번 16장에만 맞춘 임계값을 바로 제품에 적용하지 않았다. 수정 시 별도 미사용 표본과 브라우저에서도 재검증하고 사용자 제공 11인 사진의 기존 결과도 유지하는지 확인해야 한다. 현 배포의 일반적인 탐지 품질을 완료로 판정하지 않는다.
