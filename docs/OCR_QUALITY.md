# 배경 무늬 OCR 오인식 개선 — 2026-10-20

사용자가 나무 배경에서 검색 문구 178개가 잡히고 100개가 자동 포함되는 화면을 제보했다. 첨부 자료는 편집 화면 캡처이며 원본 배경 사진이 아니므로 해당 원본의 재현 성공으로 보고하지 않는다.

기존 Tesseract 7 한영 sparse-text 결과에서 줄 신뢰도 25 이상이면 문자·기호 구분 없이 채택하고 앞 100개를 자동 선택했다. 잔디·털·과일 등 실제 글자 없는 무늬에서 발생하는 문자 조각이 검색 데이터로 유입되는 원인이다.

## 처리 변경

1. 줄 신뢰도와 단어별 신뢰도를 함께 검사한다. 숫자·한글·영문을 유지하며 기호만 있는 결과·자모 파편·비정상 점수·잘못된 좌표는 제외한다. 한 글자와 두 글자는 더 강한 증거를 요구한다.
2. 후보 영역에 여백을 주고 같은 기기의 Tesseract를 한 줄 모드로 다시 실행한다. 짧은 문구는 정규화된 글자가 일치해야 하고 긴 문장은 최대 10% 문자 차이를 허용한다. 단순히 같은 sparse-text 인식을 두 번 실행하는 방식이 아니다. 별도 모델·유료 API·서버 추론을 추가하지 않는다.
3. 재확인 결과가 불안정하면 목록에서 제외한다. 양쪽 점수가 모두 85 이상인 문구만 자동 선택한다. 재확인됐지만 점수가 낮은 후보는 미선택으로 남기며 사용자가 확인해 포함할 수 있다. 점수는 정답 확률이 아니다.
4. 재확인은 강한 후보 최대 100개로 제한하고 화면의 읽기 순서를 유지한다. 사진 변경·중단 시 기존 generation gate와 worker 종료를 유지한다. 검색에 쓸 글자가 없으면 강제로 결과를 만들지 않고 안내한다.
5. 패킷에는 선택한 문구만 전송한다. 로컬 신뢰도·중간 후보·원본 사진을 인식 서비스로 보내지 않는다. 기존 글의 저장 문구는 자동 삭제하지 않는다. 기존 잘못된 결과를 고치려면 작성/수정 화면에서 `다시 읽기` 후 저장한다.

## 검증과 범위

- Windows Node 순수 규칙 유닛 62개 PASS. 실제 Android에서 수집한 잔디 오탐 후보 5개의 재확인 결과를 고정 회귀 자료로 사용한다. 좌표·미선택 전송 제외·짧은 한글/숫자·약한 단어·비정상 점수·불일치·작업 상한도 검사한다.
- Android API35 실제 시스템 WebView에서 배포 전 소스를 실행했다. 잔디, 1600px 확대 잔디, 건물 사진의 나무 부분, 털, 과일 부분, 벽돌 등 글자 없는 6개 입력의 결과는 모두 0개다. 확대와 crop은 독립 사진 수로 합산하지 않는다.
- 생성한 한영 간판 3줄과 짧은 `입구`·`OPEN`·`24` 3줄, Tesseract 공식 인쇄물 샘플 8줄을 유지했다. 생성 문구 검사는 자연 간판 정확도·전체 사진 recall 측정과 구분한다.
- 사진·출처·원시 결과·시간은 `evidence/mobile-web/ocr-quality/`, 실제 오탐 crop 회귀는 `web-tests/fixtures/ocr-texture-confirmations.json`에 보존한다. 테스트 이미지나 회귀 자료는 운영 ZIP에 들어가지 않는다.
- 추가 비용·서버 의존성을 도입하지 않으며 PythonAnywhere 서버 저장·검색 및 평가 Android 앱 동기화 계약은 유지한다. Android 네이티브 ML Kit 인식기는 이번 수정 대상이 아니다. 실제 Android WebView 검사와 평가 네이티브 앱 검사를 혼동하지 않는다.

이 제한된 표본의 오탐 0개를 모든 배경 사진의 오탐 0%로 일반화하지 않는다. 작은 글자·흔들림·반사·기울어진 간판은 더 보수적으로 제외될 수 있다. 목표 문서의 대규모 한영/혼합/어려운 사진 평가와 물리 iPhone Safari 실측은 별도이며, 재확인 시간은 후보 수에 따라 추가된다. 사용자 원본 배경 사진은 직접 검증하지 못했다.

## 실제 배포 확인

- 릴리스 `20261020092725e44d69`, PythonAnywhere phase=verified. 공개 모듈4개·실제 편집 템플릿이 로컬 소스 SHA와 일치하고 공개 자산44개가 정상이다. 기존 글1·2·3을 확인했다. WSL Django196개·HTTP20개 PASS, check0·migration 변경 없음이다.
- 배포된 `WebVision`을 그대로 Android API35 WebView에서 실행해 9개 조건 PASS. 글자 없는 6개 입력의 기존 검출216개/자동선택158개→검출0개/선택0개다. 정상 문구14줄을 모두 유지·자동선택했다. `evidence/mobile-web/ocr-quality/production-results.json`에 각 입력·결과·실측 시간과 환경을 기록했다.
- 배경 테스트는 잔디37→0, 확대 잔디158→0, 나무 부분6→0, 털12→0, 과일1→0, 벽돌2→0이다. 배포 모델의 실행 시간은 입력별 약0.8~5.2초이며 1600px 잔디가 가장 오래 걸렸다. 단일 시행이고 모델 로딩·환경 조건이 섞여 있으므로 p50/p95나 속도 목표 달성으로 주장하지 않는다.
- `production-foliage-crop.png`, `production-grass-large.png`, `production-sign.png`는 실제 Android의 ADB 원본 캡처다. **검증 전용 화면**에서 운영 인식 모듈을 실행한 사진/결과 증거이며 제품 작성 화면의 사용성 캡처로 제출하지 않는다. 원본 SHA는 결과 JSON에 보존했다. 별도 게시물 등록이나 사용자 원본 업로드는 하지 않았다.
- 재현 도구: `tools/local/verify-android-ocr.mjs <ADB CDP port> <release>`와 WSL `tools/local/verify_ocr_deployment.py <release>`. 전자는 기존 로컬 audit APK·실행 중인 AVD·포워딩이 필요하다. 테스트 작업을 마친 뒤 해당 앱과 포워딩을 종료한다.
