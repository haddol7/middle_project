# 모바일 페이지 전체 점검 — 2026-10-20

사용자가 전체 화면을 먼저 Android로 실행·캡처해 수정 대상을 확인하도록 요청했다. 제품 소스 변경 전에 실제 PythonAnywhere 사이트를 Android API35 에뮬레이터에서 점검했다. 기존 Chrome은 최초 실행 설정 상태여서 약관 동의를 대신 수행하지 않고 별도 로컬 WebView 테스트 APK를 기존 SDK로 빌드했다. 제품 Android 앱의 대체 구현이 아니라 모바일웹 레이아웃 검사 전용 도구다. WebView viewport는 412×650 CSS px이며 데스크톱 화면 크기 에뮬레이션이 아니다.

원본 Android 기기 캡처와 DOM 측정은 `evidence/mobile-web/android-ux-audit/before/`에 저장했다. `*-web.png`는 동일 Android WebView의 CDP surface 캡처지만 canvas가 누락될 수 있어 사진 확인은 ADB 원본 `.png`를 기준으로 한다. 초기에 탭 전환 직후 ADB raster가 이전 화면을 보여주는 지연을 발견해 캡처 대기와 surface 동기화를 추가했다. 측정 JSON과 화면의 선택 탭이 일치하는지 별도로 확인한다.

## 반영한 변경과 중간 재검증

공통 메뉴를 한 줄로 정리하고 계정명/로그아웃을 계정 메뉴로 옮겼다. 목록의 검색은 입력·검색 버튼 한 줄과 접는 테마/태그 필터로 바꾸었다. 검색의 GET·테마·태그·문구 조건과 페이지 이동은 유지한다. 로그인·회원가입은 짧은 폼으로 통일하고 가입 도움말은 펼칠 수 있게 배치했다. 서버 비밀번호 검증 규칙은 유지하며 사진관·마을 용어를 정정했다.

사진 선택도 viewport 크기의 편집 작업 화면으로 통일했다. 취소·사진 선택·촬영·짧은 안내를 제공하고 긴 처리 설명은 접었다. 준비 중 상태·중단을 편집기 안에 연결했다. 상세는 짧은 제목·정보와 상단 수정 버튼, viewport에 맞춘 사진 크기를 사용한다. 긴 게시글·사진 목록 전체를 무조건 한 화면으로 압축하지 않으며, 핵심 콘텐츠 앞의 불필요한 공간과 조작 버튼이 가려지는 문제를 구분한다.

첫 실제 배포 `20261020081811d0405b` 후 Android 재검사에서 목록 첫 사진 y=614→242px, 공통 헤더136→61px를 확인했다. 회원가입 완료 버튼은 기존 y=876~921에서 y=419~463px로 이동했다. 기본 화면의 개선은 650·550px에서 확인했다.

추가로 550px에서 태그 입력란의 아래쪽이 탭 스크롤 경계에 잘리는 현상을 발견해 입력 영역을 고정하고, 새 태그 칩도 가려지지 않도록 여백과 자동 노출을 보정했다. 화면 전체 좌표뿐 아니라 스크롤 부모의 경계와 `elementFromPoint`에 따른 실제 가림도 검사한다. 첫 검사에서 로그인 상태로 회원가입 URL을 열면 정상적으로 목록으로 돌아가는 동작을 폼 실패로 잘못 분류했다. 검사기는 테스트 WebView의 세션 쿠키를 메모리에만 보관했다가 비회원 폼 검사 후 원래 세션으로 복귀하도록 수정했으며 쿠키 값은 로그·파일·보고서에 기록하지 않는다.

중간 결과는 `after/first-run-results.json`·`second-run-results.json`에 보존한다. 현재 성공 여부는 최종 `after/results.json`과 키보드의 `after/keyboard.json`을 기준으로 판정한다. 이 둘을 실제 iPhone Safari 성공으로 해석하지 않는다.

## 후속 요청: 목록의 여러 게시글 동시 표시

사용자가 이어서 한 화면에 여러 글을 보여달라고 요청해 모바일 목록을 2열 그리드로 바꾸었다. 큰 본문 미리보기는 상세로 옮기고 썸네일·두 줄 제목·작성자/날짜·짧은 분류 정보로 구성했다. 첫 글만 크게 보이던 당시 캡처는 위의 이력으로 보존하며, 현재 목록은 [2열 화면](../evidence/mobile-web/post-grid/grid-393x650.png)과 [3개 크기 검사](../evidence/mobile-web/post-grid/results.json)를 따른다.

최종 릴리스 `2026102009071884b927` 실제 배포·공개 템플릿 일치 및 기존 글1·2·3 보존을 확인했다. 약393px 너비에서 650/550px 높이와 320px 너비에서 550px 높이를 실제 Android WebView로 검사했다. 각 크기에서 두 글이 완전히 보이고 세 글의 사진이 화면에 들어오며 가로 넘침이 없었다. 빈 검색 안내는 전체 폭이고 원본 사진·전체 본문은 상세에서 접근할 수 있음을 확인했다. 검색·필터·페이지 이동과 API는 유지했다.
