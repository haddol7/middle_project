# 추가 기능 선정 기록

2026-10-20 갱신. 사용자가 얼굴 모자이크와 함께 제시한 조합의 상세 기능 설명을 확인하고 “좋습니다 이 기능들을 토대로 설계를 진행해주세요”라고 요청했다. 현재 기준은 [설계 기준본](../../design-20261020/README.md)이다. 선정·설계 완료와 구현·배포 완료를 구분한다.

## 확정된 기능

**A01 얼굴 자동 모자이크**: 후기·일상 사진에 함께 찍힌 사람의 얼굴을 게시 전에 가리는 사용자 과업을 해결한다.

- 사진 선택 후 단말에서 얼굴을 검출하고 모자이크 미리보기를 제공한다.
- 얼굴별 적용/해제, 누락 영역 추가, 강도 조절, 취소·되돌리기와 최종 확인을 제공한다.
- 최종 모자이크를 이미지 픽셀에 적용한 게시 사본을 전송한다. 화면 덮개만 가린 채 원본을 공개하지 않는다. 기기 원본은 보존한다.
- 검출은 신원 식별이 아니며 누락 가능성이 있다. 사용자가 확인·보완할 수 있어야 한다.
- 공식 bundled 얼굴 검출 SDK와 Android 이미지 처리를 Codex가 구성한다. 사용자 직접 설치·모델 훈련은 필요하지 않은 경로다. 실제 검출 품질·기기·게시 파일 검증은 구현 후 수행한다.
- 기존 Post 업로드·이미지 제공을 사용하므로 추가 등록은 Android1개로 본다. 별도 서버 기능을 인위적으로 만들지 않는다.
- 이전 평가의 F10 "얼굴·연락처 노출 점검"에서 **얼굴 모자이크에 집중한 확정 범위**다. 연락처 OCR 자동 검출은 이번 선정에 포함하지 않았다. F10 전체의 과거 점수를 이 좁혀진 범위의 새 측정값으로 주장하지 않는다.

**A02 자동 테마·태그 분류**: 이전 후보 F01. 최종 게시 사진의 내용으로 대표 테마·태그를 추천하고 사용자가 수정한다. 확정값을 실제 서버에 저장하고 테마·태그별로 다시 찾는다. 추가 서버1+Android1.

**A03 사진 속 글자 검색**: 이전 후보 F02. 최종 게시 사진의 한글·영문 문구를 인식·교정·검색 제외하고 서버에서 조회한다. 결과를 열면 해당 문구가 있던 영역을 표시한다. 추가 서버1+Android1.

## 채택하지 않은 대안

F05 관련 사진글과 추천 이유, F06 관심 테마별 발견 피드는 이번 조합에 포함하지 않는다. 연락처 자동 노출 점검, 광범위한 사진 편집, 의미 기반 자연어 검색도 추가로 채택하지 않았다. 과거 후보 원자료와 점수는 그대로 보존한다.

## 조합과 흐름 검토

| 검토안 | 사용자 기능 | 추가 서버 | 추가 Android | 등록 합계 |
| --- | --- | ---: | ---: | ---: |
| A · 선정 | A01 얼굴 모자이크 + A02 자동 분류(F01) + A03 사진 속 글자 검색(F02) | 2 | 3 | 5 |
| B | A01 얼굴 모자이크 + F01 자동 분류 + F05 관련 글 추천 | 2 | 3 | 5 |
| C | A01 얼굴 모자이크 + F01 자동 분류 + F06 관심 테마 피드 | 2 | 3 | 5 |

기본 과제 ID1–13과 실제 PythonAnywhere 서버·Android 동기화는 모든 조합의 전제다. 숫자는 ID14 서버/클라이언트 별도 등록에 맞춘 설계 가정이며 독립 기능 인정은 실제 기능 정의와 증빙이 필요하다.

후보 A의 연결 흐름은 사진 선택→얼굴 모자이크 확인→최종 게시 사본 확정→해당 사본으로 테마/OCR 분석→결과 확인·게시→서버 저장·검색이다. OCR과 내용 분석은 최종 공개할 사본을 기준으로 하며, 사용자가 가린 내용이 이전 분석 결과에 남지 않도록 사진 변경 시 결과를 무효화·재분석한다. 이는 기능 사이의 일관성 조건이며 새로운 추가 기능 슬롯이 아니다.

공통 조건: 무료 PythonAnywhere 범위에서 실제 게시글·분류·검색 데이터를 저장/조회하고, 인식은 Android에서 수행한다. 외부 핵심 서버·유료 API·사용자 수동 모델 준비·모델 학습을 전제로 하지 않는다. 과거 35개 평가 원자료는 비교 기록으로 보존한다.
