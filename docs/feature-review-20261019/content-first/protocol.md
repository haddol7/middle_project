# 필요성 우선 독립 평가 지침

이 문서와 brief.md를 함께 따른다. 후보 확정본은 candidates.json, 등록 단위는 components.json이다. 과거 점수·다른 평가자의 원자료를 읽지 않고 새로 평가한다. 필요성 없는 고난도 기능을 가중 평균으로 구제하지 않는다.

## 평가 순서

1. **필요성 gate**: 어떤 사진 블로그 과업에서 왜 필요한가. core=일반적인 게시·정리·찾기·열람/발견 문제에 직접 연결, niche=특수 촬영물/개인 취향/제한된 상황에서 유용, weak=핵심 과업과 약한 연결·기본 동작 재포장·불필요한 편집. 가정한 사용자 상황은 가설이며 사용자 조사로 입증됐다고 쓰지 않는다. core는 N>=7, niche는 4<=N<7, weak는 N<4로 채점한다.
2. **환경·Codex gate**: pass/hold/exclude. 실제 무료 PA와 Android에서 구체 SDK/모델/알고리즘 경로, 자동 의존성 구성, 합성/공개 검증자료와 실행 검증 경로가 있어야 pass. 사용자 수동 설치·공부·라벨링·모델 훈련·강화학습 필요 시 pass 금지. ML Kit 일반 인식 SDK와 제한 기기용 생성형 SDK를 혼동하지 않는다. 실제 사진 정확도는 구현 후 검증할 대상으로 명시한다.
3. **점수**: N 필요성30, T 기술 도전성40, U UI/UX20, E 과제 차별성·결과 증빙10. 각 0–10, 0.5 단위. `N*3+T*4+U*2+E`=100. 작업량·일정·현실성 점수는 없다. T는 가장 높은 단일 비중이며 어려움은 가점이다. 단일 SDK 호출을 모델 연구·자체 ML 개발 난도로 채점하지 않는다.
4. **등록·중복 감사**: 후보의 components와 requires 폐쇄가 실제 동작을 모두 담는지 본다. 공유 라이브러리는 별도 사용자 기능이 아니다. 서로 대안인 후보와 부모 기능의 작은 화면 확장을 독립 가점 여러 개로 주장하지 않는다. 파생 기능이 인식 결과를 필요로 하면 원천 분석/저장/Android 입력 경로를 포함한다.

## 점수 앵커

- N 9–10: 사진의 제목/수동 태그 부족 같은 반복적인 핵심 문제를 직접 해결. N7–8.5: 명확한 일반 과업 효과가 있으나 기존 기본 흐름으로도 해결 가능. N4–6.5: 일부 촬영물·상황에만 필요. N0–3.5: 사진 블로그로서의 목적이 약함.
- T9–10: 유용한 동작에 필수인 복수 알고리즘/랭킹·색인/비동기 상태/동기화의 정합성을 높은 수준으로 결합. T7–8.5: 인식 SDK와 데이터 모델·검색/좌표·교정·실패 상태를 실제로 통합. T4–6.5: 알려진 SDK 결과를 단순 표시·단순 집계. 인위적 복잡성은 점수 근거가 아니다.
- U는 완성된 화면의 명료함, 세밀한 상태/피드백, 사진 중심 정보 위계·조작을 평가한다. 구현이 어렵거나 화면이 많다는 이유로 감점하지 않는다.
- E는 필수 기능과 구분되는 사용자 효과·기술을 실제 Android↔PA 동작과 테스트/시연으로 입증하는 힘이다. 테스트 만들기 어려움·시간은 감점하지 않는다.

## 결과 집계

- 세 평가자 모두 core 및 모든 Codex/platform gate pass, 수동작업/훈련 false일 때만 **핵심 추천 순위**에 포함한다.
- 필요성 판정이 갈리면 핵심 순위 밖에 판정 이견을 표시한다. niche/weak 및 환경 보류/제외 목록도 점수와 사유를 공개한다. high T가 gate를 덮지 않는다.
- 점수는 3인 평균, 동점은 N 최저점→N 평균→T 평균→ID 순. 작업량을 동점에 쓰지 않는다.
- 기능별 점수와 서버/클라이언트 등록 단위는 서로 다르다. 예시 조합은 컴포넌트 집합으로 최대5개·서버/클라이언트 균형·중복·의존성을 검사한다. 후보 점수 평균을 부품 점수인 것처럼 최적화하지 않는다.
- 기존 앱 코드/배포/소스 콘셉트는 변경하지 않는다. 평가 자료 작성은 기능 선정이나 구현 승인과 다르다.

## 출력 스키마

각 평가자는 review-product.json / review-technical.json / review-assessment.json 중 본인 파일만 작성한다. 모든 고정 후보 ID를 한 번씩 평가하며 다른 평가자 결과를 읽지 않는다.

```json
{"reviewer":"product","rubric":"NeedGate-N30-T40-U20-E10","rows":[{"id":"F01","N":8,"T":7,"U":8,"E":8,"need":"core","needReason":"사진을 게시할 때마다 내용을 직접 분류하는 과업을 줄인다. 사용자 연구로 입증한 수요는 아니다.","codexGate":"pass","platformGate":"pass","userManualWork":false,"trainingRequired":false,"implementation":"구체 SDK/알고리즘과 Android·PA 담당 동작","dependencies":"모델 취득/자동 구성·기기 지원·서버 저장 범위","verification":"WSL·Windows/Android 및 실제 PA 검증 경로와 실패/오인식 검증","demo":"교수님께 보여줄 사용자 동작과 비교 결과","overlaps":[],"componentIssue":"none","recognitionRisk":"medium","note":"필요성·도전성·차별성과 한계를 설명"}],"blindSpots":[]}
```

N/T/U/E 범위·0.5 단위, ID 완전성, gate enum, bool, 필수 문자열을 Node로 검사한다. componentIssue는 none 또는 실제 미포함 동작/추가 등록 필요 사유. 조합 채택에 영향을 주는 의존성 누락이 있으면 보고하며 임의로 축소해 pass하지 않는다. officialSources는 선택 배열로 추가할 수 있다.
