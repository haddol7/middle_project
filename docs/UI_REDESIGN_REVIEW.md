## 다음 구현의 완료 기준

1. 타깃 사용자·주요 목적·핵심 과업과 각 기능의 필요성을 확정한다.
2. Android의 첫 실행 → 사진 열람 → 게시 → 개인 공간 이용 → 다른 사용자 방문 흐름을 과업에 맞게 설계한다. 콘셉트가 바뀌면 해당 과업명과 기능 범위도 다시 정의한다.
3. 화면 초안에서 현재 위치·주요 행동·입력 오류·진행 중·저장 완료·취소·재접속 경로를 검토한다.
4. 기존 데이터·사진·평가 API 계약·권한·저장 충돌·업로드 성공 후 중복 게시 방지를 보존하고, 바꾸는 기능의 요구사항·테스트·증빙을 함께 갱신한다.
5. WSL 서버 검증, Windows Android 빌드·기기 검증, 실제 화면 검수를 수행한다. 과업을 모르는 사용자의 사용성 검증은 별도로 기록한다.

환경 복원 테스트 통과는 현재 기능이 실행된다는 증거다. 이 UI 재설계나 사용성 목표를 달성했다는 증거로 사용하지 않는다.
