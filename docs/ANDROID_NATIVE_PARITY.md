# Android 앱 반영 내역 — 2026년 10월 20일

모바일웹에서 정리한 작성·편집 방식을 Java PhotoViewer에도 반영했다. Android 앱은 WebView로 대체하지 않았다. 사진 처리와 인식은 기기의 ML Kit, 게시·분류 저장·검색은 기존 PythonAnywhere Django API를 사용한다.

## 바뀐 화면과 처리

| 부분 | 반영 내용 |
| --- | --- |
| 목록 | 사진 카드를 두 열로 배치하고 제목 길이를 제한했다. 긴 본문 대신 테마·태그와 검색에 일치한 문구를 표시한다. 테마·태그 필터는 필요할 때 펼친다. |
| 얼굴 편집 | 바깥 화면을 스크롤하지 않는 작업 공간으로 바꿨다. 사진은 남는 높이를 사용하고 이동·선택·그리기·되돌림과 적용 버튼은 아래에 유지한다. 선택한 도구는 색으로 구분한다. |
| 영역 설정 | 강도·가림 해제·삭제·정밀 이동·크기 변경은 선택 영역의 설정 메뉴에 모았다. 다시 찾기는 직접 만든 영역을 유지한다. |
| 게시 전 확인 | 글 작성·태그·검색 문구의 세 탭으로 나눴다. 제목과 본문, 사진 교체, 얼굴 재편집, 게시 동작을 유지한다. |
| 태그 | 선택·추천 태그를 칩으로 표시한다. 누르면 선택을 바꾸고, 직접 입력해서 추가할 수 있다. 최대 10개·태그당 30문자와 중복 정리 규칙은 기존 서버 규격을 따른다. |
| 검색 문구 | 각 문구마다 편집 카드를 만들던 구조를 없앴다. 높이가 제한된 선택 목록과 공통 교정 입력칸을 사용한다. 선택한 줄의 위치를 사진에 표시하고, 모두 포함·제외·검색 미사용·재인식을 지원한다. |
| 키보드 | Android 15의 화면 가장자리 및 키보드 영역을 반영한다. 입력 중에는 사진과 보조 도구를 접어 교정칸과 게시 버튼이 키보드 위에 남도록 했다. |
| 공개 상세 | 전체 OCR 문구 목록은 계속 숨긴다. 검색에 일치한 위치 선택과 원본 사진 확대는 유지한다. 기울어진 문구는 사각형 네 꼭짓점으로 그린다. |
| 얼굴 탐지 | 작은 얼굴이 있는 큰 사진은 겹치는 부분 사진에서도 찾는다. 새로 발견한 영역은 주변을 포함한 사진에서 재확인하고 중복을 합친다. 수동 보완과 실제 픽셀 모자이크를 유지한다. |
| OCR | 영문·한글 결과를 선별하고 잘라낸 영역에서 재확인한다. 글자·신뢰도 조건을 통과하지 못한 짧은 배경 무늬는 버린다. 종이 문서는 임시 이미지의 기울기를 보정해 재인식하고 위치를 원래 사진으로 되돌린다. 게시 사진 자체를 회전시키지 않는다. |
| 확인이 필요한 OCR | 문서 재인식 결과는 확인 전 미선택이다. 일반 사진도 두 번의 인식이 충분히 확실한 경우에만 자동 선택한다. 제외한 문구는 검색 서버에 보내지 않는다. |
| 연결·권한 | 새 설치의 기본 주소는 `https://daejinha.pythonanywhere.com/`이다. 지정 운영자 권한은 서버 응답을 따르며 회원가입이나 사진관 기능을 추가하지 않았다. |

## 실행한 검증

Windows에서 `PhotoViewer/tools/verify-android.ps1 -RunDevice -Server http://127.0.0.1:8010/`을 실행했다. 실제 Gradle 빌드, JVM 단위검사 38개, lint 오류 0개, Android 기기 검사 9개가 통과했다. lint 경고 8개는 남아 있다. 소스 및 APK 해시는 `evidence/content/android/verification.json`에 기록했다.

기기 검사는 WSL Ubuntu의 임시 데이터베이스·미디어와 테스트 운영자를 사용했다. 실제 사진 선택, 얼굴 탐지·모자이크 픽셀 및 원본 보존, 분류, 한영 OCR, 교정, 게시, 재생성 복원, 검색, 위치 표시, 권한·수정 충돌을 확인했다. 글자 없는 배경 6조건과 정상 인쇄문 보존 검사를 추가했다. 운영 블로그에 테스트 글을 만들지 않았다.

같은 APK로 840×1470px·420dpi, 약 320×560dp의 작은 화면에서도 UI 흐름 1개를 별도로 완주했다. 사진과 완료 버튼의 실제 위치를 검사하고 키보드를 연 화면을 캡처했다. 작은 화면 캡처 8개와 해시는 `evidence/content/android/small-screen/`에 있다.

`CloudSyncTest`는 실제 PythonAnywhere HTTPS에서 게시글과 사진을 읽어 해시를 대조하고 앱의 사진 표시를 확인한다. 읽기 전용이며 운영 환경에서 게시·수정·삭제를 실행한 검사로 집계하지 않는다. 결과와 화면은 `cloud-sync.json`, `content-cloud-sync.png`에 기록한다.

Android OCR의 원본 좌표 33개, 이 중 첨부 손글씨의 좌표 25개는 WSL에서 `blog.content_rules.validate_quad`로 검증했다. Windows Python으로 Django를 실행한 결과가 아니다.

## 인식 결과와 한계

- 사용자 단체사진의 얼굴 11곳을 확인했다. 공개 단체사진 9장의 주석 43개 중 42개가 IoU 0.25 이상으로 대응했다. 주석 외 검출 8개도 있었다. 해당 사진에는 배경 인물과 벽의 인물 그림이 있으므로 이를 모두 배경 오탐으로 계산하지 않는다. 누락 1개가 남아 있어 자동 탐지 후 직접 확인하는 절차는 필요하다.
- 배경 6조건의 문구 검출은 모두 0개였고, 인쇄 페이지 8줄은 유지했다. 생성한 한글·영문 간판도 실제 기기 검사에서 확인했다. 이 결과가 모든 자연사진의 정확도를 보장하지는 않는다.
- 첨부 손글씨는 기존 32개 파편·중복 후보 대신 보정한 문서에서 25개 후보가 나왔다. 25개 모두 확인 전 미선택이며 약 9.4초가 걸렸다. 후보 수의 감소를 단어 정확도 향상 수치로 해석하지 않는다. 실제 철자 오류와 누락은 남는다.
- 웹은 MediaPipe/Tesseract, Android는 ML Kit를 사용한다. 기능과 확인 흐름을 맞춘 것이며 같은 모델이나 동일 인식률이라고 주장하지 않는다. 검사용 원본 첨부파일과 원시 인식문은 `.local`에 보관하고 인식 결과 JSON에는 개수와 검증 범위만 기록했다. APK에는 사용자 사진을 넣지 않았다. 운영 목록 화면 캡처에는 사용자가 현재 공개한 게시물의 사진 썸네일이 보인다.
- 새 로직이 기존 게시글을 자동으로 재분석하지는 않는다. 기존 글은 수정 화면에서 다시 분석한 뒤 확인·저장해야 변경된다.

보고서 본문과 증빙은 I34에서 최신화했다. 실제 iPhone Safari 검사, 웹의 검색 일치 영역 보완, 최종 제출·GitHub 업로드는 남아 있다.
